## 一、产品概述

### 1.1 产品愿景

把微信好友的几千条聊天记录, 变成每天早上 5 条可行动的建议——该联系谁、该推进什么、什么逾期了、关系在降温还是在升温。

### 1.2 目标用户

| 角色 | 典型场景 | 微信好友规模 |
|------|---------|------------|
| 销售/商务 | 管理客户关系、识别商机、群发营销 | 1000–5000 |
| 创业者/管理者 | 维护人脉网络、追踪承诺、经济往来 | 500–3000 |
| 个人用户 | 关系温度监控、关键事件提醒、消费记账 | 200–2000 |

### 1.3 核心差异化

传统 CRM 是人手动录入 → 人手动分析 → 人手动行动。本系统是 AI 自动采集 → AI 自动画像 → AI 自动洞察 → AI 建议行动 → 人确认/自动执行。

### 模块 A: 账号管理

#### A.1 我的微信标识

**描述**: 显示当前登录微信账号信息。

**数据来源**: UIA 读取微信窗口标题 / `wechat_friend WHERE is_self=1` / 本地配置

**字段**:
| 字段 | 来源 |
|------|------|
| 头像 | UIA 截取头像区域图片 |
| 昵称 | UIA 读取 / DB 查询 |
| 微信号 | UIA 读取资料页 / DB 查询 |
| 微信版本 | 进程路径 Weixin.exe 文件版本 |
| 在线状态 | 进程是否运行 (PID 检测) |
| 上次同步时间 | `wechat_operation_log` 最近一条 collect 记录 |

**优先级**: P0

**验收标准**:
- [ ] 头像/昵称/微信号正确显示
- [ ] 微信进程状态实时检测 (2s 轮询)
- [ ] 上次同步时间准确

---

#### A.2 切换微信

**描述**: 退出当前微信 → 弹出登录二维码 → 用户扫码 → 新账号上线。

**流程**:
1. 确认退出当前微信
2. 若 Weixin.exe 运行 → 调用退出
3. 重新启动微信 → 等待登录窗口
4. 用户扫码
5. 检测到登录成功 → 更新本地配置 → 触发首次全量采集

**优先级**: P1

**验收标准**:
- [ ] 退出-扫码-登录流程完整可操作
- [ ] 登录后自动触发通讯录+聊天采集

---

#### A.3 退出微信

**描述**: 关闭 PC 微信进程。

**操作**: 发送 `WM_CLOSE` 消息 / 模拟点击关闭按钮 / 强制结束进程 (fallback)

**优先级**: P1

**验收标准**:
- [ ] 微信进程正常退出
- [ ] 异常情况可强制结束

### 模块 B: 数据同步

#### B.1 好友信息同步

**描述**: 从微信 PC 客户端通讯录全量采集所有好友/群, 写入 wechat_friend / wechat_group 表。

**采集流程** (已有: `collect_contacts.py`):
1. 确认微信窗口存在
2. 切换到"通讯录" Tab
3. 展开所有分组 (CellGroupView)
4. 滚动遍历联系人列表
5. 点击每个联系人 → 读取右侧资料面板
6. 提取: 昵称、微信号、备注、地区、签名、来源、添加时间、共同群聊
7. 按 contact_type 分类入库 (friend/group/official_account/new_friend/starred 等)
8. 去重 (wxid UNIQUE)

**采集范围**: 支持全量 / 增量 (仅采集上次同步后新增的)

**优先级**: P0 (已有, 需集成到前端)

**验收标准**:
- [ ] 全量采集完成率 > 95% (部分假号/已注销号可能失败)
- [ ] 采集进度实时显示 (当前第N个, 已入库M个)
- [ ] 增量模式正确识别新增联系人
- [ ] 去重逻辑正确 (按 wxid 唯一)

---

#### B.2 聊天信息同步

**描述**: 采集指定好友/群的聊天记录, 写入 wechat_chat 表。

**采集流程** (已有: `msg_collect.py` + `msg_traverse.py`):
1. 搜索目标联系人 → 打开聊天窗口
2. 从最新消息开始向上滚动 (PageUp)
3. 逐条读取消息: 发送者、内容、类型、时间戳
4. 识别消息类型: text / image / file / voice / system / date_sep
5. 入库去重 (content + msg_ts 去重)

**采集范围**:
- 全量采集: 遍历所有会话 → 逐会话采集全部消息
- 增量采集: 仅采集上次同步后产生的新消息
- 指定好友: 只采集某个好友的聊天记录

**优先级**: P0 (已有, 需集成到前端)

**验收标准**:
- [ ] 文本消息完整采集 (含 emoji/特殊字符)
- [ ] 消息时间戳准确 (与微信客户端一致)
- [ ] 图片/文件消息记录 file_path
- [ ] 消息去重正确
- [ ] 增量采集不重复

---

#### B.3 同步日志

**描述**: 记录每次同步操作的时间、范围、结果。

**数据来源**: `wechat_operation_log` 表

**字段**: operation | target | result | detail | duration_ms | created_at

**优先级**: P1

**验收标准**:
- [ ] 每次同步自动记录日志
- [ ] 日志可查询/筛选

#### D.3 好友详情 — Tab 2: 画像·关系 (核心差异化功能)

**描述**: 好友的立体画像, 8 维度关系评分雷达图 + 13 树关系分类 + AI 人物速写 + 关键事件时间线 + 经济往来。

##### D.3.1 8 维评分雷达图

| 维度 | 含义 | 影响因素 |
|------|------|---------|
| 亲密度 (closeness) | 有多亲近 | 聊天频率、内容深度、见面次数、称呼变化 |
| 信任度 (trust) | 有多信任 | 秘密分享、金钱来往、托付事项、守约记录 |
| 尊重度 (respect) | 有多尊重 | 语气、用词、是否倾听 |
| 好感度 (affection) | 喜不喜欢 | emoji 使用、正向词汇、主动联系频率 |
| 商业价值 (biz_value) | 生意潜力 | 行业/职位/决策权/采购意向/合作历史 |
| 成长价值 (growth_value) | 能学到什么 | 对方专长、经验分享、指导机会 |
| 经济信用 (credit_score) | 借还记录 | 借款是否按时还、代付是否结清 |
| 互惠度 (reciprocity) | 有来有往 | 双方付出对比、谁更主动 |

**评分范围**: 0–100, 初始值 50, AI 从聊天分析计算

**交互**:
- 雷达图直观展示 8 维分布
- 点击维度查看详细说明
- 支持手动调整 (拖拽/输入, 标记为 manual_override)
- 显示评分趋势箭头: ↗ 上升 ↓ 下降 → 持平 (近30天对比)

**关系总分公式**:
```
total = closeness×0.25 + trust×0.20 + respect×0.10 + affection×0.10
      + biz_value×0.15 + growth×0.10 + credit×0.10
```

**优先级**: P1

**验收标准**:
- [ ] 雷达图正确渲染 8 个维度
- [ ] 鼠标悬停显示维度详情
- [ ] 手动编辑保存后标记 override
- [ ] 趋势箭头正确反映 30 天变化

##### D.3.2 13 树关系分类

**描述**: 每个好友可被归入多棵分类树 (M:N), 每棵树有 `大类 → 子类 → 级别(1/2/3)`。

**13 棵分类树**:

| # | 树名 | 主要子类 | 级别含义 |
|---|------|---------|---------|
| 1 | 血缘关系 | 直系血亲 / 旁系血亲 / 姻亲 | 1=亲近 2=一般 3=冷淡 |
| 2 | 亲戚 | 自由填写 (堂兄/表妹/…) | 1=常来往 2=偶尔 3=不联系 |
| 3 | 同乡/老乡 | 同村 / 同镇 / 同县 / 同市 / 同省 | 1=常来往 2=偶尔 3=不联系 |
| 4 | 同学 | 小学→博士 + 培训班 (按时间段) | 1=铁哥们 2=普通 3=不联系 |
| 5 | 战友 | 同年兵 / 同连队 / 同部队 | 1=生死之交 2=战友情 3=一般 |
| 6 | 同事 | 按时间段+公司+职位关系+前同事 | 1=亦师亦友 2=普通 3=有过节 |
| 7 | 客户/生意伙伴 | A/B/C/D/流失客户 | 1=VIP 2=正常 3=僵死 |
| 8 | 供应商 | 核心 / 备选 / 曾合作 | 1=战略 2=正常 3=已终止 |
| 9 | 同行/竞品 | 直接竞争 / 间接 / 可合作 | 1=友好 2=中立 3=敌对 |
| 10 | 供应链 | 上游 / 下游 / 物流 / 服务商 | 1=核心 2=一般 3=边缘 |
| 11 | 兴趣/圈子 | 自由标签 (球友/读书会/教会…) | 1=核心成员 2=参与者 3=边缘 |
| 12 | 邻居 | 现邻居 / 曾邻居(年份) | 1=好友 2=点头 3=不往来 |
| 13 | 其他/未分类 | AI 分析后自动归类 | - |

##### H.1.2 行动优先级算法

```
P = urgency_score × 0.4 + importance_score × 0.6

urgency_score:
  逾期/即将到期                  → 1.0
  最后沟通>30天+重要关系          → 0.8
  生日/纪念日<3天                → 0.7
  商业信号 (询价/招标)            → 0.9
  一般周期性提醒                  → 0.4

importance_score:
  直系血亲                        → 1.0
  A级客户                         → 0.9
  B级客户 / 领导                   → 0.7
  铁哥们 / 闺蜜                    → 0.6
  C级客户 / 普通好友               → 0.4
  D级 / 一面之交                   → 0.2

行动分级:
  P ≥ 0.8 → 🔴 今天必须做
  P ≥ 0.5 → 🟡 本周内做
  P ≥ 0.3 → ⚪ 有时间做
  P < 0.3 → 📋 存档备查
```


**四条派遣路径**:

| 路径 | 触发条件 | 流程 |
|------|---------|------|
| 即时执行 | P ≥ 0.7 且非敏感操作 | 洞察 → 生成话术 → 自动发送 |
| 定时派遣 | 周期性提醒 | 洞察 → 创建 cron job → 到期执行 |
| 待办列队 | P < 0.7 | 洞察 → 加入 TODO → 用户手动触发 |
| 人工确认 | 涉及金钱/敏感关系 | 洞察 → 推送通知 → 用户审批 |

**优先级**: P1

---

#### H.2 反馈闭环

```
执行行动 → 等待对方响应 (下次聊天采集) →
  ├─ 有回复 → AI 分析回复 → 亲密度+N / 标记成功 → 更新画像
  └─ 无回复 → 亲密度-1 / 降优先级 → N天后重新生成行动 (换话术)
```

#### H.3 自动化规则引擎

**描述**: 用户可自定义自动化规则 (IF 条件 THEN 行动)。

**规则模型**:
```json
{
  "name": "重要客户每周维护",
  "condition": {
    "customer_level": { "in": ["A", "B"] },
    "last_contact_days": { ">": 7 }
  },
  "action_type": "SEND_MESSAGE",
  "priority_base": 0.5,
  "dispatch_method": "todo",
  "schedule": "0 9 * * 1"
}
```

**优先级**: P3

## 五、非功能需求

### 5.1 性能

| 场景 | 指标 |
|------|------|
| 好友列表加载 (4000条) | < 1s (首次), < 200ms (后续, 缓存) |
| 聊天记录加载 (10万条) | 首次加载 < 2s, 滚动加载无延迟 (虚拟滚动) |
| AI 画像分析 (单个好友) | < 30s (异步) |
| 洞察引擎扫描 (全量) | < 5min (每天凌晨 cron, 异步) |
| 消息采集 (单个好友, 500条) | < 3min (UIA 操作) |
| 群发消息 (100人) | < 20min (间隔 5-8s) |

### 5.2 安全

- 微信登录凭据本地加密存储
- 聊天记录不外传 (本地分析)
- PAT 令牌不在日志中暴露
- 敏感字段 (借款金额/手机号) 可加密存储

### 5.3 可靠性

- UIA 操作失败自动重试 3 次
- 消息入库事务保护 (出错回滚)
- 长时间采集任务支持断点续传
- 微信进程异常退出后自动重连

### 5.4 可用性

- 所有表单字段提供中文标签和 placeholder
- 错误信息用中文 + 可操作的建议
- 长耗时操作显示进度条 (不能取消的要说明)
- 关键操作提供确认弹窗 (删除/退出/群发)
