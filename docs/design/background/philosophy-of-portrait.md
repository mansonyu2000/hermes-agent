# 人头画像的哲学基础 · 一个人到底是什么

> 上帝视角：当 AI 助理真正了解一个人时，它看到的是一个
> **立体的、有原则的、会拒绝的、在成长的、有故事的人**，
> 而不是一张扁平的数据表格。

---

## 一、人是什么 — 哲学源流

### 1.1 儒家：人是关系中的存在

儒家不孤立地看人。一个人是他所有关系的总和。

**五伦**（人的五种基本关系）：
| 关系 | 应有之德 | 数据化 |
|------|---------|--------|
| 君臣（上下级） | 忠、敬 | 对领导/下属的态度模式 |
| 父子（亲子） | 孝、慈 | 与父母/子女的互动模式 |
| 夫妇（伴侣） | 和、贞 | 亲密关系的质量 |
| 兄弟（手足） | 悌、友 | 与兄弟姐妹的互助模式 |
| 朋友 | 信、义 | 对朋友的诚信和义气 |

**五常**（人的五种核心德性）：
- **仁** — 是否利他？帮过人吗？拒绝对别人不好的事？
- **义** — 是否公正？做了正确而非有利的选择吗？
- **礼** — 是否得体？知道什么场合做什么事吗？
- **智** — 是否明智？做决策时是否理性分析？
- **信** — 是否可靠？答应的事做到了吗？

**中庸** — 不走极端。30/30/40 的比例本身就体现了中庸之道：不贪婪地追求 100%，而是聚焦在真正重要的 60%。

### 1.2 基督教：人是有限而蒙恩的

- **七美德**：信/望/爱/智/义/勇/节 → 做了哪些体现这些美德的事？
- **七宗罪**：骄傲/贪婪/嫉妒/愤怒/色欲/贪食/懒惰 → 主人对这些的警惕程度
- **宽恕** — 被伤害后是否原谅？还是记恨？
- **管家精神** — 主人把自己的时间/金钱/才能看作"受托管理的"，还是"我自己的"？

### 1.3 佛教：人是由"业"和"选择"构成的

- **因果** — 每一个选择都有结果。主人是否理解并承认这一点？
- **五戒** — 不杀生/不偷盗/不邪淫/不妄语/不饮酒 → 主人的底线是什么？
- **慈悲** — 是否主动帮助弱者？捐过款吗？
- **放下** — 能否放下执念？还是执着于某些事？
- **觉知** — 对自己行为的觉察程度

### 1.4 现代心理学

- **马斯洛需求层次** — 主人当前在哪一层？生理→安全→归属→尊重→自我实现
- **依恋类型** — 安全型/焦虑型/回避型/混乱型 → 影响所有人际关系
- **价值观排序** — 自由 vs 安全、成就 vs 关系、创新 vs 传统、个人 vs 集体

### 1.5 经济学视角

- **人的资源分配**：时间/金钱/注意力/情感 花在了哪里？
- **机会成本**：拒绝了 A 而选择了 B = B 是 A 的机会成本
- **比较优势**：主人最擅长什么？（别人花 2 小时的，他 30 分钟做完）
- **风险偏好**：保守 vs 激进 → 投资/职业/社交决策都受此影响

## 二、拒绝的价值 — "不"塑造了人

> 一个人是谁，不在于他做了什么，而在于他**选择不做什么**。
> 每次拒绝都是一次自我定义。

### 2.1 为什么拒绝是重要的数据

```
每一次"不"都在说：
  "这个不符合我的价值观"
  "这个超出了我的边界"
  "我判断这个风险太大"
  "我有更重要的事"
  "这个人不值得我帮"
  
  → 拒绝 = 一个人的轮廓
```

### 2.2 拒绝事件分类

```sql
CREATE TABLE personal_refusal (
    id          BIGINT PRIMARY KEY AUTO_INCREMENT,
    refusal_date DATE NOT NULL,
    
    -- 谁发起的请求
    requester_uid VARCHAR(128),          -- 请求者 (关联到 wechat_friend)
    requester_relation VARCHAR(64),      -- 当时的关系
    
    -- 请求内容
    request_type VARCHAR(16) NOT NULL,   -- money/job/favor/time/item/endorsement/investment/date/other
    request_detail TEXT,                 -- 具体内容: "借10000块, 说做生意周转"
    request_amount DECIMAL(12,2),        -- 如有金额
    
    -- 我的反应
    response_type VARCHAR(16) NOT NULL,  -- flat_no/soft_no/delayed/redirected/conditional
    reason        VARCHAR(32),           -- why: boundary/risk/values/priority/trust/ability
    my_response   TEXT,                  -- 我实际说了什么
    
    -- 后果
    impact_on_relation VARCHAR(8),       -- positive/neutral/negative
    their_reaction     VARCHAR(32),      -- 对方的反应
    was_i_right        TINYINT,          -- 事后看我是对的吗？ 0=no 1=yes NULL=未知
    
    -- 事后反思
    reflection     TEXT,                 -- AI 或主人事后的反思
    would_i_change TINYINT DEFAULT 0,    -- 如果再来一次，我会改变吗
    
    created_at     DATETIME DEFAULT CURRENT_TIMESTAMP,
    INDEX idx_date (refusal_date),
    INDEX idx_type (request_type),
    INDEX idx_requester (requester_uid)
);
```

### 2.3 拒绝的统计价值

```
统计报告示例：

"2024 年你拒绝了 47 次请求:
  - 借钱 12 次 (¥86,000) → 避免了 7 笔坏账
  - 介绍工作 8 次
  - 帮忙 15 次 (时间有限)
  - 投资邀请 5 次 (3 个后来暴雷)
  - 借东西 4 次

你的拒绝模式:
  拒绝借钱 → 边界明确，信用把关好
  拒绝帮忙 → 时间管理意识强
  拒绝投资 → 风险意识偏保守（对你有保护作用）

你的拒绝类型分布:
  flat_no(直接拒绝)  32%  → 你比较直接
  soft_no(委婉拒绝)  45%  → 但也照顾对方面子
  redirected(转介)   18%  → 你愿意帮但不是亲自帮
  conditional(有条件) 5%

拒绝最多的 3 个人:
  张三(8次) → 关系可能已失衡
  李四(5次) → 该重新评估这段关系
  
学到了什么:
  - 3 个被你拒绝的请求，事后证明是对的（张三的借款果然没还别人）
  - 1 个你后悔拒绝了（王五的项目其实不错）
"
```

### 2.4 拒绝与哲学的一致性检验

| 哲学体系 | 对应的问题 | 数据来源 |
|---------|-----------|---------|
| 儒家·义 | "这个请求在道义上对吗？" | 拒绝理由含 'values'/'boundary' |
| 儒家·智 | "答应了会有什么后果？" | 拒绝理由含 'risk'/'ability' |
| 佛家·戒 | "这会伤害别人或自己吗？" | 拒绝理由含 'boundary' |
| 基督·管家 | "这是我的时间/钱，我受托管理的" | 拒绝理由含 'priority' |
| 现代·边界 | "这是我该做的吗？" | 拒绝理由含 'boundary' |

## 三、主人做了什么 — 正面清单

> 主人不是被动的存在。他主动做了什么？他帮助了谁？他改变了什么？

### 3.1 给予清单

```
2024 年你主动做了:
  借钱给朋友      ¥25,000 (3人)
  请客            47 次 (¥8,900)
  介绍工作机会     5 次 (3 人成功)
  免费提供专业咨询  12 次 (总计约 36 小时)
  帮人搬家/修东西   3 次
  捐款             ¥1,200 (4次)
  献血             2 次
  教别人技能        8 次
  介绍客户/资源     11 次
  情感支持          (无法量化，但很重要)
  
总结: 你是一个愿意付出的人，尤其是知识型帮助和职业机会。
     你的弱项: 不太擅长主动情感关怀（AI提醒: 多给家人打电话）。
```

### 3.2 选择清单（关键决策）

```
2024 年重大决策:
  ✓ 拒绝了 A 公司的 offer → 选择了 B 公司 (薪资+30%)
  ✓ 开始学 TypeScript
  ✓ 停止炒股，转为指数定投
  ✓ 搬到了离公司更近的地方 (通勤从1.5h→20min)
  
决策风格分析:
  职业决策: 偏理性 (数据驱动)
  消费决策: 偏冲动
  人际决策: 偏保守 (回避冲突)
  
AI 建议: 消费决策前给自己设 24 小时冷静期。
```

## 四、四维画像模型 — 一个人的立体面貌

```
           精神高度
              △
             /|\     ← 信仰、价值观、哲学立场、人生意义
            / | \
           /  |  \
          /   |   \
         /    |    \
        /     |     \
       /      |      \
      /       |       \
     /        |        \
    ──────────┼──────────→ 关系广度
    ← 过去    │    未来 →    ← 所有人脉、社会角色
    时间深度  │
              │
              ▽
            物质基础
         ← 健康、财富、技能、消费
```

### 4.1 四个维度

| 维度 | 问题 | 核心指标 |
|------|------|---------|
| **精神高度** | 为什么活着？ | 信仰、价值观、人生目标、座右铭、拒绝原则 |
| **关系广度** | 和谁在一起？ | 人脉网络、角色扮演、给予/接受、关系评分 |
| **时间深度** | 从哪里来到哪里去？ | 出生→成长→现在→未来、关键转折点、未完成的事 |
| **物质基础** | 靠什么活着？ | 健康、财富、技能、消费、资产 |

### 4.2 拒绝在四维模型中的位置

```
拒绝 = 精神高度的外显

一个人不做什么 → 体现了他的价值观
一个人拒绝谁   → 体现了他的边界
一个人后悔了什么 → 体现了他的成长

"我可以做什么" → 物质基础
"我愿意做什么" → 主动给予
"我不做什么"   → 精神高度 ← 这就是拒绝的价值
```

## 五、30/30/40 分法 — 聚焦有价值的部分

### 5.1 分法逻辑

```
100% 的人生数据
├── 30% 重点关注 (高频查看、每日提醒)
│   ├── 核心关系 (亲密度 Top 20%、商业价值 Top 10%)
│   ├── 财务警戒 (逾期款、预算超支)
│   ├── 健康基线 (体重/BMI/运动频率)
│   ├── 待办 P0/P1
│   ├── 拒绝记录 (大的、有后果的拒绝)
│   ├── 价值观一致性 (我的行为是否符合我的信仰？)
│   └── 风险信号 (关系在流失、健康在恶化、钱在变少)
│
├── 30% 关注 (每周查看)
│   ├── 一般关系维护
│   ├── 学习进度
│   ├── 消费分类统计
│   ├── 月度目标完成度
│   ├── 爱好/娱乐记录
│   └── 事件日志 (中等重要)
│
└── 40% 可忽略/归档 (按需查看)
    ├── 日常琐事
    ├── 一面之交的联系人
    ├── 已完成的旧任务
    ├── 看过就忘的娱乐内容
    └── 系统自动生成的日志
```

### 5.2 AI 如何判断重要度

```
重要性评分 = f(金钱, 关系, 时间, 情感, 价值观)

金钱权重: >¥10,000 = 重点关注; >¥1,000 = 关注; 其他 = 可忽略
关系权重: 亲密度>80 或 商业价值>70 = 重点关注
时间权重: 截止日期<3天 = 重点关注; <7天 = 关注
情感权重: 正面/负面情绪强度>3 = 关注
价值观权重: 涉及拒绝/道德选择 = 重点关注 (无论金额)
```

### 6.2 一个人 = 一个故事

> 数据库记录的是事实，但一个人是一个**叙事**。
> AI 的最终目标不是输出一堆数字，而是能讲出这个人的故事。

```
"于杨敏的故事" (AI 生成):

  1978 年出生于湖南一个小县城，父亲是中学老师，母亲是护士。
  小时候家里穷但书多，养成了阅读的习惯。
  
  1996 年考到武汉的大学，学计算机。大二开始在电脑城打工攒经验。
  
  2000 年毕业进了深圳一家小公司做程序员，月薪 ¥3,000。
  做了 3 年跳到了华为，一做就是 12 年，从工程师做到了技术总监。
  
  2015 年遇到许国勇（同一个项目组的同事），成了铁哥们。
  许国勇2018年离职去了腾讯，两人保持半年见一次的频率。
  
  2018 年结婚。老婆是湖南人（老家介绍的）。有一个女儿，今年 5 岁。
  
  2020 年离开华为，去了现在的公司做 CTO。管理 40 人的团队。
  年收入约 ¥XXX，在深圳有一套房（有贷款），一台丰田凯美瑞。
  
  他是一个"信"做得很好的人（答应的事基本都做到），
  但"礼"(社交礼仪) 偏弱（不太主动维护关系）。
  
  他拒绝过的东西：
  - 拒绝了赵六借 ¥50,000（理由是风险太大，事实证明他是对的）
  - 拒绝了前同事拉他创业（他觉得自己不适合创业）
  - 拒绝了 3 个猎头的 offer（觉得时机不对）
  
  他的矛盾：
  - 想做更多开源贡献 vs 工作太忙
  - 想多陪女儿 vs 加班是常态
  - 想戒烟 vs 压力大时一天两包
  
  他最近在想：
  - 40 岁了，下一步是什么？继续管技术还是转型？
  - 女儿马上要上小学了，学区房要不要换？
  - 要不要帮父母在长沙买套房养老？
  
  AI 的判断：
  - 他是一个有底线、有专业能力、偏内向的人。
  - 他最需要的是：时间管理的优化 + 关系维护的提醒 + 健康改善计划。
  - 他的"信"是他最大的资产，他拒绝的能力保护了他。
```

## 七、被我们忽略但很重要的维度

### 7.1 "没有做"的清单

| 维度 | 追踪方式 |
|------|---------|
| 没联系的人 | 超过 N 天没互动的亲密好友 → 提醒 |
| 没学的技能 | 计划了但一直拖延 → 提醒 |
| 没去的旅行 | 说了很多次但没成行 |
| 没说出口的感谢 | AI 从聊天中识别"该感谢但没说" |
| 没还的人情 | TA 帮过你但你还没回报 |
| 没追的梦想 | 年轻时想过但放弃了 → AI 提醒"你以前说过想..." |

### 7.2 "无形的资产"

| 维度 | 数据来源 |
|------|---------|
| 人脉的可信度 | 介绍的人是否靠谱 → 追踪转介绍的成功率 |
| 口碑 | 别人对你的评价 → 从聊天中提取 |
| 影响力 | 你发的消息被多少人转发/讨论 |
| 被依赖程度 | 多少人遇到问题第一反应是找你 |
| 幽默感 | AI 分析聊天中的玩笑频率和反应 |

### 7.3 "未完成的清单"

一个活着的人一定有"未完成"。这些未完成定义了当下的焦虑和动力。

| 类型 | 示例 |
|------|------|
| 未完成的承诺 | "下周请你吃饭"→ 2周了没请 |
| 未完成的还款 | 借了许国勇 ¥20,000 约定 12 月还 |
| 未完成的学习 | TypeScript 学到 40% 停了 |
| 未修复的关系 | 和张三冷战了 3 个月 |
| 未了结的事情 | 前公司的期权还没处理 |
| 未处理的情绪 | 某件事一直让你不舒服但没说出来 |

## 十、数据优先级的 30/30/40 在代码中的体现

```python
# 伪代码: AI 画像更新的优先级调度

def prioritize_updates(uid):
    """根据 30/30/40 原则决定哪些数据更新"""
    
    # 30% 重点关注 — 每次聊天后立即更新
    hot_fields = [
        'closeness', 'trust', 'biz_value',        # 核心关系分
        'credit_score',                            # 信用
        'refusals_large',                          # 大额拒绝
        'values_consistency',                      # 价值观一致性
        'health_alerts',                           # 健康警报
        'overdue_items',                           # 逾期未完成
    ]
    
    # 30% 关注 — 每天更新一次
    warm_fields = [
        'hobby_activity',                          # 爱好
        'learning_progress',                       # 学习
        'expense_trend',                           # 消费趋势
        'medium_relations',                        # 中等关系
        'decision_review',                         # 决策回顾(1月/6月/1年)
    ]
    
    # 40% 可忽略 — 每周/每月更新
    cold_fields = [
        'entertainment_log',                       # 娱乐记录
        'casual_contacts',                         # 偶尔联系人
        'old_tasks',                               # 已完成旧任务
        'routine_logs',                            # 日常流水
    ]
    
    return hot_fields, warm_fields, cold_fields
```

这两者之间的差距，就是一个人成长的空间。
