## 设计哲学概要

把微信好友的几千条聊天记录，变成每天早上 5 条可行动的建议——该联系谁、该推进什么、什么逾期了、关系在降温还是在升温。

核心差异：传统 CRM 是人手动录入 → 人手动分析 → 人手动行动。本系统是 **AI 自动采集 → AI 自动画像 → AI 自动洞察 → AI 建议行动 → 人确认/自动执行**。

## 八大评估维度

| 维度 | 评分来源 | 权重 |
|------|---------|:--:|
| **亲密度** | 聊天频率、对话深度、互动时长 | 20% |
| **信任度** | 隐私话题比例、经济往来记录、承诺兑现率 | 15% |
| **尊重度** | 称呼方式、回复速度、请求响应率 | 10% |
| **喜爱度** | 正向情感词频率、表情使用、主动联系比例 | 10% |
| **商业价值** | 交易金额、合作项目数、推荐价值 | 20% |
| **成长价值** | 知识分享、行业洞察、资源引荐 | 10% |
| **信用度** | 借钱还钱记录、承诺兑现 | 10% |
| **互惠度** | 互相帮助次数、资源互换频率 | 5% |

## 行动闭环

```
画像 → 分析 → 洞察 → 派遣 → 执行 → 反馈 → 更新画像
  ↑                                                    │
  └────────────────────────────────────────────────────┘
```

### 每天 5 条行动建议示例

1. **关系升温**：与 XX 已 14 天未联系，关系温度下降 8%，建议发送问候
2. **商机跟进**：XX 上次提到采购需求，距今 7 天，建议跟进确认
3. **承诺追踪**：你答应给 XX 发资料，距今 3 天未完成
4. **人脉维护**：XX 本月生日，建议提前 3 天准备祝福
5. **洞察预警**：XX 近 30 天回复速度下降 60%，关系可能疏远

## 双存储架构

```
wechat_chat (MySQL) ← 原始聊天记录
        │
        ▼
friend_score_log (MySQL) ← AI 评分结果
        │
        ▼
actionable_insight (MySQL) ← 可执行洞察
        │
        ├── 仪表盘 TodayActionList
        └── Hermes 工具 winpeek_execute_insight
```

**存储原则**：原始数据不可变（wechat_chat），评分可重算（friend_score_log），洞察可标记已读/已执行（actionable_insight）。
