## 状态感知四问

每次操作前必须回答：

| 问题 | 方法 |
|------|------|
| **我在哪** | `get_current_page()` 检测当前页面 |
| **我要去哪** | 目标页面/目标分组 |
| **怎么去** | `navigate_to(target)` 规划路径 |
| **到了没** | 验证目标元素可见且尺寸正常 |

## 三层定位

| 层级 | 方法 | 速度 | 可靠性 | 适用场景 |
|------|------|:--:|:--:|---------|
| Tier 1 | UIA AutomationId | 0.1s | 最高 | 日常操作 |
| Tier 2 | 位置记忆（自学习） | 0.2s | 越用越准 | 重复操作加速 |
| Tier 3 | 像素锚点（布局规律） | 0.3s | 永远可靠 | UIA失效兜底 |

## 街道/店铺隐喻

```
街道 = 一级导航栏（微信、通讯录、收藏...）
       → 永远在窗口左侧，不会消失，不需要"回"
       → 想去哪个街道，直接点导航按钮

店铺 = 二级分组（群聊、公众号、联系人...）
       → 在通讯录这条街上，每个分组是一个店
       → 进错了店 → 关门 → 换对的店
       → 不需要回街上再进，就在街上直接换门
```

## 三步极简门检测

```
while 目标门不在眼前:
    if 有展开的门挡着:
        关掉它（含跳页组）  # 腾空间
    else:
        报告"无能为力"      # 所有门都关了还看不见 → 求外援
开目标门 → 完成
```

**核心洞察**：任何展开的分组，点击其标题均可折叠——包括"新的朋友"和"我的企业"。

## 虚拟列表三戒

微信通讯录是 Qt VirtualList——只渲染可见区域的 ~20 个 UIA 元素，滚动时回收复用。

**核心认知：UIA 元素的生命周期只有一帧。拿到矩形 → 点击前，元素可能已被回收。**

| 戒律 | 错误做法 | 正确做法 |
|------|---------|---------|
| **戒存矩形** | Phase1 存 `(name, rect)` 到队列，Phase2 直接用 | 队列只存 `(name, type)`，点击前**实时按名重定位** |
| **戒污染 seen** | wxid 重复时 `seen.add((name, type))` | wxid 重复时**不入 seen**——你不知道点到的到底是谁 |
| **戒碰边界** | 把可见区全部新人入队处理 | 队列 `len>1` 时 **`pop()` 最后一个**——它正被虚拟列表回收 |

## 窗口三区布局

```
┌──────────────────────┬─────────────────────────┐
│ ① 左上角原点 (0,0)   │  ③ 右上角控制区         │
│  所有相对坐标的零点   │  (最小化/最大化/关闭)    │
├──────────────────────┤                         │
│ ② 左侧导航区         │  内容区（可变）          │
│  col1: 图标栏 60px   │                         │
│  col2: 二级列表 240px│                         │
│  (窗口<360px col2收缩)│                         │
├──────────────────────┤                         │
│ ④ 底部功能区         │                         │
└──────────────────────┴─────────────────────────┘
```

**关键原则**：只有 col1+col2 是像素固定的。内容区和窗口高度可变，不能依赖绝对像素值。

## RPA 核心原则

- **任何展开的门都能关**：点标题即可折叠，包括跳页组
- **三步极简法**：找目标 → 有关门 → 重复；不要加复杂 fallback
- **虚拟列表**：只操作 UIA 可见元素，屏外元素用像素锚点兜底
- **ESC 绝对禁用**：ESC=隐藏微信窗口，Ctrl+Alt+W 恢复
- **一级导航永远在**：直接点目标按钮，不需要"回首页"
